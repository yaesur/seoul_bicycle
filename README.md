# 서울시 공공자전거 흐름 불균형 분석 및 재배치 우선순위

> 2025년 4–6월 서울시 공공자전거 이용 이력을 바탕으로 시간·공간별 흐름 불균형을 분석하고, 가깝고 불균형이 큰 대여소 쌍의 검토 우선순위를 제안한 도시 모빌리티 데이터 프로젝트입니다.

## 프로젝트 한눈에 보기

공공자전거는 이용 수요가 특정 시간과 장소에 집중되면서 어떤 대여소에는 자전거가 몰리고 다른 곳에는 빠져나가는 문제가 발생합니다. 이 프로젝트는 약 2천만 건 규모의 OD 집계 데이터를 처리해 다음 질문에 답합니다.

1. 출근·퇴근·여가 시간대의 흐름 불균형 분포는 다른가?
2. 유입 과잉과 유출 과잉은 서울의 어느 지역에 집중되는가?
3. 가까운 과잉·부족 대여소 중 어떤 쌍을 현장에서 먼저 확인해야 하는가?

## 핵심 정의

대여소 `i`, 기간 `t`의 흐름 불균형 proxy를 다음과 같이 정의합니다.

```text
B(i,t) = 반납 건수(i,t) - 대여 건수(i,t)
NB(i,t) = B(i,t) / (반납 건수(i,t) + 대여 건수(i,t))
```

- `B > 0`: 관측 기간의 유입 과잉
- `B < 0`: 관측 기간의 유출 과잉
- `|B|`: 운영 개입이 필요할 가능성의 크기

중요: 이 값은 시점별 실제 보유 자전거 수가 아니라 누적 대여·반납 흐름의 차이입니다. 따라서 본 프로젝트는 이를 “재고 부족”이 아닌 “흐름 불균형 proxy”로 일관되게 해석합니다.

## 분석 설계

| 구분 | 정의 |
|---|---|
| 분석 기간 | 2025년 4월 1일–6월 30일 |
| 출근 | 평일 07:00–09:59 |
| 퇴근 | 평일 17:00–20:59 |
| 여가 | 주말·공휴일 12:00–18:59 |
| 통계 분석 | Kruskal–Wallis, epsilon-squared, Friedman 검정 |
| 기준선 | 무재배치, 최근접 greedy |
| 제안 모델 | 거리·불균형 결합 우선순위 점수 |
| 운영 지표 | 연결 가능 불균형, 거리, 우선순위 등급 |

점수는 연결 가능한 불균형과 양쪽 불균형이 클수록 높아지고 거리가 멀수록 낮아집니다. 결과는 실제 이동 명령이 아니라 현장 재고를 먼저 확인할 후보 순서입니다.

## 공식 ID 매핑 결과

OD 데이터의 `시작_대여소_ID`와 `종료_대여소_ID`를 서울시 실시간 대여소 API의 공식 `stationId`에 직접 조인했습니다.

| 시간대 | 분석 대여소 | 공식 좌표 매핑 | 미매핑 | 매핑률 |
|---|---:|---:|---:|---:|
| 출근 | 2,487 | 2,426 | 61 | 97.5% |
| 퇴근 | 2,563 | 2,493 | 70 | 97.3% |
| 여가 | 2,308 | 2,249 | 59 | 97.4% |

기존 대여소명 기반 카카오 검색의 약 16–20% 매핑률을 공식 ID 조인으로 97% 이상까지 개선했습니다. 남은 항목은 폐쇄·신설·ID 변경 가능성이 있어 2025년 6월 반기별 마스터와 추가 대조해야 합니다.

## 우선순위 모델

```text
연결 가능량 = min(과잉량, 부족량)

우선순위 점수 = 연결 가능량 × √(과잉량 × 부족량) / (거리 + 0.5km)
```

웹 데모에서는 시간대를 바꾸고 상위 10·20·30개 후보를 확인할 수 있습니다. 각 후보는 출발·도착 대여소, 거리, 대표일 연결 가능 불균형, 상대 우선도와 선정 이유를 표시합니다.

별도의 운영 시나리오에서는 시간대 전 사전 배치 총량과 차량 적재량을 설정합니다. 우선순위대로 공급·부족 한도 안에서 물량을 배분해 `어디서 → 어디로 → 몇 대`, 예상 흐름 불균형 완화율, 경로 수와 차량 운행 횟수를 보여줍니다. 출근·퇴근 방향을 함께 비교해 주거지형, 업무지형, 지속 부족형, 지속 과잉형 정책도 자동 제안합니다.

## 빠른 시작

Python 3.10 이상을 권장합니다.

```bash
python -m venv .venv
.venv/Scripts/activate
pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m src.fetch_station_master
python -m src.build_web_data
python -m http.server 8000
```

그다음 `http://localhost:8000/simulation/`을 엽니다. 정적 웹 데모만 확인할 때는 Python 패키지를 설치할 필요가 없습니다.

## 재현성과 데이터 관리

원천·중간 데이터 약 4.8GB와 개인 분석 노트북은 Git에서 제외했습니다. 로컬 파일은 그대로 유지되며, 공개 저장소에는 데이터 설명, 소량 표본, 집계된 웹 데모 데이터만 포함합니다. 서울시 API 키는 코드에 저장하지 않고 `SEOUL_OPEN_DATA_API_KEY` 환경변수에서만 읽습니다.

## 연구 윤리와 한계

개인 식별 정보는 사용하지 않았습니다. 좌표는 서울시 공식 대여소 ID를 기준으로 연결했습니다. 실제 운영 정책으로 사용하려면 시점별 재고·거치대 용량·도로망 이동시간·차량 경로와 계절 외부검증을 추가해야 합니다.

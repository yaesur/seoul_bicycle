# 사용한 코딩 기법·모델·통계기법

## 데이터 엔지니어링

### 청크 처리

약 3GB의 정제 CSV를 한 번에 메모리에 올리지 않고 75만 행 단위로 읽습니다. 각 청크에서 필요한 컬럼만 선택하고 시간대별 집계를 누적해 대규모 데이터에서도 메모리 사용량을 제한했습니다.

### 벡터화와 GroupBy

행 단위 반복 대신 pandas의 불리언 마스크와 `groupby().sum()`을 사용합니다. 날짜에서 평일·주말·공휴일을 다시 계산해 기존 파생변수 오류가 결과에 전파되지 않도록 했습니다.

### 공식 ID 기반 데이터 조인

OD 데이터의 `시작_대여소_ID`, `종료_대여소_ID`를 서울시 API의 `stationId`와 조인합니다. 대여소명 문자열 검색보다 정확하며, 2025년 6월 공식 대여소 파일의 대여소 번호를 추가 연결해 자치구와 상세주소를 보완했습니다.

### API 페이지네이션과 비밀 관리

서울시 API의 1,000건 제한에 맞춰 여러 페이지를 요청합니다. 키는 소스코드나 `.env`에 기록하지 않고 `SEOUL_OPEN_DATA_API_KEY` 환경변수에서만 읽습니다.

## 분석 지표

### 흐름 불균형 proxy

```text
B(i,t) = 반납 건수(i,t) - 대여 건수(i,t)
NB(i,t) = B(i,t) / (반납 건수(i,t) + 대여 건수(i,t))
```

`B > 0`은 유입 과잉, `B < 0`은 유출 과잉입니다. 웹에서는 누적값을 관측일 수로 나눈 대표일 값을 사용합니다. 이는 실제 재고가 아니라 대여·반납 흐름의 차이입니다.

## 공간 모델

### Haversine 거리

위도·경도로 두 대여소의 대권거리를 계산합니다. 도로망 거리가 없는 탐색 단계에서 빠르게 근거리 후보를 만들기 위한 근사치입니다.

### 재배치 우선순위 점수

```text
연결 가능량 = min(과잉량, 부족량)
점수 = 연결 가능량 × sqrt(과잉량 × 부족량) / (거리 + 0.5km)
```

불균형 규모가 크고 거리가 가까운 쌍을 높은 순위로 배치합니다. 100m 미만은 좌표 중복 가능성, 5km 초과는 근거리 운영 범위를 이유로 후보에서 제외합니다. 이 모델은 머신러닝 예측모델이 아니라 설명 가능한 규칙 기반 공간 의사결정 모델입니다.

### 제한 예산 배분

사용자가 설정한 사전 배치 총량을 높은 우선순위부터 공급량·부족량 한도 안에서 배분합니다. 경로별 이동량을 차량 적재량으로 나누고 올림해 예상 운행 횟수를 계산합니다.

### 출퇴근 연계 유형화

- 주거지형: 출근 유출 과잉, 퇴근 유입 과잉
- 업무지형: 출근 유입 과잉, 퇴근 유출 과잉
- 지속 부족형: 두 시간대 모두 유출 과잉
- 지속 과잉형: 두 시간대 모두 유입 과잉

방향 전환을 이용해 업무지의 아침 도착 자전거를 퇴근 수요에 보존하고, 지속 부족지는 외부 공급 대상으로 제안합니다.

## 통계기법

### Kruskal–Wallis 검정

출근·퇴근·여가 시간대별 대여소 절대불균형 분포가 같은지 비교하는 비모수 검정입니다. 정규성 가정이 어려운 치우친 불균형 분포에 적합합니다.

### Epsilon-squared 효과크기

표본 수가 클 때 p-value만으로 차이를 과장하지 않도록 시간대가 불균형 분산을 얼마나 설명하는지 함께 보고합니다.

### Friedman 검정

동일한 대여소를 출근·퇴근·여가 시간대에 반복 측정한 구조로 보고 시간대 차이를 비교하는 비모수 반복측정 검정입니다.

## 프런트엔드 기법

- Leaflet 레이어 그룹으로 대여소와 후보 경로를 분리해 다시 그립니다.
- 원 반지름은 절대 불균형의 제곱근에 비례시켜 극단값이 지도를 압도하지 않게 합니다.
- 자치구 검색 결과는 절대 불균형 내림차순으로 정렬합니다.
- 검색 지역만 다시 우선순위화해 서울 전체 후보와 지역 내 후보를 동시에 제공합니다.
- 상태 객체와 순수 계산 함수를 분리해 시간대·검색·시나리오 변경 시 일관되게 다시 계산합니다.
